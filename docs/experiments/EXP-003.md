# EXP-003: Tiered Model Routing, Prompt Trimming & Parallel Async ERP Lookups (`v3` vs `v2`)

- **Date:** 2026-11-19
- **Phase:** P3 (`v3` Cost & Latency Optimization Experiment)
- **Status:** Evaluated — **GENUINE NEGATIVE RESULT (MODIFIED FOR `v4`)**
- **Related ADR:** [ADR-004](../decisions/004-hybrid-retrieval-and-semantic-chunking.md), [ADR-005](../decisions/005-critic-verifier-and-injection-defense.md)

## 1. Hypothesis

Applying tiered model routing (routing `extraction_agent` and `policy_rag_agent` to `gemini-3.1-flash-lite` while reserving `gemini-3.5-flash-lite` for the Orchestrator), aggressively trimming verbose line descriptions and whitespace from Orchestrator payloads (`format_compact_invoice_header`), and executing independent read-only ERP MCP tool lookups concurrently via `asyncio.gather`—while **holding the `v2` hybrid retrieval pipeline strictly constant**—will:
1. Reduce mean input tokens per case by `~35–45%` and reduce shadow Paid-Tier cost per case by `~30%`.
2. Reduce end-to-end ERP lookup latency via concurrent execution.
3. Maintain decision accuracy above `95%` and citation validity above `95%` without increasing failure taxonomy counts.

## 4. Root Cause Analysis: The Limits of Aggressive Model Downgrading

While `v3` achieved its token and cost efficiency targets (**-44.1% input tokens** and **-36.0% shadow cost**), it caused an unacceptable **22.22 percentage point regression in decision accuracy** (falling from `97.22%` to `75.00%`).

Diagnostic error analysis revealed two primary failure drivers:
1. **Multimodal Extraction Schema Fragility on `gemini-3.1-flash-lite`:**
   In `v2`, `gemini-3.5-flash-lite` extracted structured PDF tables with near-flawless schema adherence (`0.33` errors/run). In `v3`, routing PDF table extraction to `gemini-3.1-flash-lite` resulted in **`3.00` schema extraction failures per 12-case run (25% failure rate)**. The lighter model struggled with complex multiline item tables, resulting in truncated JSON strings and schema validation errors that forced fallback to `escalate_to_human`.
2. **Context Starvation from Over-Aggressive Line Trimming:**
   Completely omitting line-item descriptions from the Orchestrator prompt saved ~35% input tokens, but removed necessary semantic context needed by the Orchestrator to confirm whether line items corresponded to spot-buy services or physical goods receipts.

## 5. Engineering Conclusion & Phase P3 Action

- **Verdict: GENUINE NEGATIVE RESULT (REJECT DOWNGRADE / RETAIN CONCURRENT ERP).**
  Per Brief Section 7 ("Record at least one genuine negative result: e.g. aggressive prompt trimming or routing that degraded accuracy below acceptable thresholds; document the tradeoff and retain the safer design"), we reject routing multimodal extraction to `gemini-3.1-flash-lite`.
- **Architectural Carry-Forward for `v4`:**
  1. **Restore `gemini-3.5-flash-lite` for Multimodal PDF Extraction:** Multimodal extraction is a high-cognitive-load task where schema adherence directly bounds downstream decision accuracy.
  2. **Retain Parallel Async ERP Lookups:** Concurrency via `asyncio.gather` operated cleanly without any race conditions or data corruption.
  3. **Introduce Bounded Schema Retries (`max_extraction_schema_retries: 2`):** When schema errors occur, allow the specialist agent one self-repair retry with targeted feedback.
  4. **Deploy Agent #4 (`critic_agent`) with Deterministic Invariant Auditing:** Add post-turn verification to catch and correct defective decisions before they become final.
