# EXP-002: Semantic Clause Chunking, Active-Version Metadata Filtering & Hybrid BM25 + Vector Reranking (`v2` vs `v1`)

- **Date:** 2026-11-18
- **Phase:** P3 (`v2` Retrieval Experiment)
- **Status:** Completed — **KEEP** (`v2` promoted as baseline for `v3`)
- **Related ADR:** [ADR-004](../decisions/004-hybrid-retrieval-and-semantic-chunking.md)

---

## 1. Hypothesis

Replacing `v1`'s naive 420-character sliding-window cosine search (`policy_chunks_v0`) with atomic semantic clause chunking (`policy_chunks_v2`), a hard `status = 'active'` metadata filter, deterministic anomaly query expansion, and hybrid scoring (`0.50` dense `gemini-embedding-2` cosine + `0.25` Okapi BM25 + `0.25` domain topic reranker)—while **holding agent topology, models (`gemini-3.5-flash-lite`), prompts, and sequential ERP tool execution strictly constant**—will:
1. Eliminate superseded `v1.0` trap clause contamination (`POL-02-V1#1`, `POL-05-V1#1`, `POL-09-V1#1`) from `~48%` down to **`0.00%`**.
2. Raise policy retrieval `Recall@5` from `90.28%` to **`100.00%`** and `MRR` from `0.6708` to **`1.0000`**.
3. Eliminate `v1`'s remaining `reasoning_error` cases (`0.67/run` $\rightarrow$ `0.00/run`) and push end-to-end decision accuracy above `95%` without increasing token spend.

---

## 2. Controlled Change (Single Variable Group: Retrieval Pipeline Only)

| Dimension | `v1` Multi-Agent (`EXP-001`) | `v2` Hybrid Retrieval (`EXP-002`) |
|---|---|---|
| **Chunking Granularity** | Naive 420-char fixed windows, 60-char overlap (`policy_chunks_v0`) | Atomic `PolicyClause` boundaries (`25` clauses in `policy_chunks_v2`) |
| **Version / Status Filter** | Unfiltered (`active` + `superseded` mixed) | Hard SQL pre-filter: `WHERE status = 'active'` (`19` active clauses) |
| **Ranking Function** | Dense `gemini-embedding-2` cosine similarity only | Hybrid `0.50 * cosine + 0.25 * Okapi_BM25 + 0.25 * topic_rerank` |
| **Query Formulation** | Raw `policy_rag_agent` free-text query | `build_hybrid_query_expansion` (agent query + deterministic anomaly tags) |
| **Agent Topology** | 3 ADK `Agent`s (`extraction`, `policy_rag`, `orchestrator`) | **Unchanged** (3 ADK `Agent`s) |
| **Active Models** | `gemini-3.5-flash-lite` (`temperature=0.0`), `gemini-embedding-2` | **Unchanged** (`gemini-3.5-flash-lite`, `gemini-embedding-2`) |
| **ERP Lookup Execution** | Sequential MCP tool calls | **Unchanged** (sequential; parallelization isolated for `v3`) |

---

## 3. Expected Effect

- **Retrieval:** `Recall@5` reaches `100%` across `golden_12`, `dev_240`, and `test_160`; `MRR` rises from `~0.68` to `~1.00`; superseded `V1` trap contamination drops to `0.0%`.
- **Outcome & Citations:** Decision accuracy and `citation_validity_rate` both improve by `+10` to `+15 pp` because `orchestrator_agent` receives complete, unsplit active clause definitions (`POL-02-V2#2`, `POL-03#2`, `POL-12#1`) at rank 1 without conflicting legacy `V1` thresholds.
- **Cost:** Slight reduction (`~5–15%`) in input tokens and shadow USD/case because concise atomic clauses replace overlapping 420-char fragments and `policy_rag_agent` rarely needs a second `search_policy` call.

## 7. Cost & Latency Impact

- **Live Spend:** `$0.00` (Google AI Studio Free Tier).
- **Shadow Paid-Tier Cost:** Decreased by **14.0%** (`$0.00412` $\rightarrow$ `$0.00354/case`) because `policy_rag_agent` converged in a single `search_policy` call (`4.61` mean LLM calls vs `4.78` in `v1`) and atomic clause text was shorter than overlapping 420-char windows (`7,142` vs `7,527` mean input tokens).
- **Latency:** Run 1 achieved faster median and tail latency than `v1` (`p50 = 17.81s`, `p95 = 27.21s`), whereas Runs 2 and 3 encountered transient AI Studio Free-Tier HTTP queuing spikes (`p95 = 109.94s` and `126.83s`), inflating multi-run latency variance (`ci95 = ±132.4s`). Reducing token volume, routing extraction/RAG to faster `gemini-3.1-flash-lite`, and parallelizing ERP calls in `v3` (`EXP-003`) directly targets this latency bottleneck.

---

## 8. Decision & What I Learned

- **Decision:** **KEEP `v2`** as the retrieval foundation for `v3` and `v4`.
- **Key Lessons:**
  1. **Better chunking *without* metadata governance makes version traps worse:** In the ablation (`v2a`), switching from naive 420-char windows to clean clause chunks raised `Recall@5` from `90.0%` to `100.0%` on `dev_240`, but *increased* superseded `V1` contamination from `47.5%` to `50.0%` because full `V1` clauses embed more cleanly than chopped windows. Metadata filtering (`status = 'active'`) is non-negotiable for versioned enterprise policies.
  2. **Hybrid lexical + topic scoring closes the rank-1 gap (`MRR 0.896` $\rightarrow$ `1.000`) for free:** Dense embeddings capture topic similarity, while Okapi BM25 + anomaly topic tags lock onto exact threshold tokens (`2%`, `10%`, `60 days`, `POL-12#1`) without paying latency or tokens for an LLM reranker.
  3. **Trace-level inspection pinpointed a subtle SDK/serialization bug (`FL-007`):** The single remaining error across 36 `v2` runs (`INV-4219`, Run 1) had the *right* decision (`reject`) and *right* citations (`POL-01#2`, `VEN-019`) inside the model response, but failed `json.loads` because multi-part text joining inserted a literal `\n` inside `"MISSING_OR_INVALID\n_PO"`. We isolate the fix for `v4` (`EXP-005`) alongside bounded schema retries and Critic verification.
